# AIMA RADIO 网站更新流程

`opt` 是本地内容库。除本文件外，整个目录都被 Git 忽略，不会上传到 GitHub，也不会进入 GitHub Pages。网页使用的压缩图片和文章数据由导入脚本生成；音频始终从 Cloudflare R2 播放。

## 1. 准备一期内容

在 `opt/radio` 下新建文件夹，名称必须使用：

```text
YYYY:MM:DD vol.N YYYYMMDD - Title
```

示例：

```text
2025:08:11 vol.1 20250731 - Oboro
```

其中：

- `2025:08:11` 是发布日期，会显示在 news 列表中。
- `vol.1` 是期数。
- `20250731 - Oboro` 是页面标题，也是 R2 音频文件名。

每期文件夹需要包含：

```text
cover.JPG                 正方形封面，必须有
doc.txt                   中文正文，必须有
doc.en.txt                英文正文，必须有
20250731 - Oboro.mp3      本地校验音频，也可以是 m4a
其他 JPG、PNG、HEIC       内页照片，可放任意数量
```

`doc.txt` 与 `doc.en.txt` 的结构相同：第一段是标题，第二段是文章小标题或曲目说明，从第三段开始是正文。段落之间留一个空行。

## 2. 上传音频到 R2

将最终 MP3 上传至 R2 存储桶的 `radio` 文件夹，文件名必须与内容文件夹末尾一致：

```text
radio/20250731 - Oboro.mp3
```

公开地址应为：

```text
https://audio.aimaradio.com/radio/20250731%20-%20Oboro.mp3
```

在手机和电脑上分别打开该地址，确认能够播放或下载。不要把 MP3 放入 `assets`，也不要执行 `git add -f opt`。

## 3. 生成网站内容

在项目根目录执行：

```bash
node tools/import-content.mjs
```

脚本会自动完成以下工作：

- 读取全部符合命名规则的节目文件夹。
- 将中文和英文正文写入 `content.js`。
- 根据真实音频计算时长。
- 将 JPG、PNG、HEIC 转成网页图片，输出到 `assets/content/`。
- 按发布日期倒序排列节目。
- 将 `vol.1` 的 R2 音频设置为主页背景音乐。
- 读取 `opt/demo` 的版本文件并生成 demo 版本树。
- 读取 `opt/track` 中的完成作品。
- 读取 `opt/note` 中的图文记录。
- 更新 `opt/音频元数据.md`，无需手动填写时长、大小和码率。

### Demo

每个作品使用独立文件夹，例如：

```text
opt/demo/demo-mis/
  mis.mp3
  mis_pt2.mp3
  mis_pt3_v2.mp3
```

音频上传到 R2 的 `demo/`，网页会按本地文件的修改日期排列版本并显示为树。列表封面由代码根据作品名和版本名稳定生成；不同作品具有不同的轨迹、分支与节点排列，无需另做封面。

### Track

每首完成作品使用独立文件夹，例如 `opt/track/Ω/`，其中放入音频、封面、中文说明 `doc.txt` 和英文说明 `doc.en.txt`。封面优先选择 `cover.JPG`，没有时使用目录内第一张图片。同名音频上传到 R2 的 `track/`（无需增加作品子目录）。音频仍只上传到 R2，图片与文字随网站项目发布。导入器也兼容直接放在 `opt/track/` 顶层的旧结构。

### Note

图文目录放在 `opt/note/`，目录格式为 `YYYY:MM:DD 标题`。其中放入 `doc.txt`、`doc.en.txt` 和需要展示的图片。

脚本使用 macOS 自带的 `sips`，并需要本机可执行 `ffmpeg` 和 `ffprobe`。

## 4. 本地检查

执行：

```bash
node tools/serve.mjs
```

打开 `http://127.0.0.1:4173`，至少检查：

1. 首页最新一期封面和 8 期列表是否正确。
2. 中英文切换后，每期标题、日期和正文是否完整。
3. 每期封面是否为正方形，内页照片是否全部出现。
4. 点击或拖动字符进度条后，播放位置是否正确。
5. 手机尺寸下正文、浮动图片和播放器是否正常。
6. 主页背景音乐能否播放，并且是否与单期音频互斥。

检查结束后按 `Ctrl+C` 停止本地服务器。

## 5. 构建和发布

执行：

```bash
node tools/build.mjs
git status
git add content.js index.html script.js styles.css assets/content assets/fonts assets/images tools opt/网站更新流程.md opt/音频元数据.md
git commit -m "Add AIMA RADIO episode"
git push origin main
```

推送 `main` 后，GitHub Actions 会生成 `_site` 并部署 GitHub Pages。自定义域名只改变访问入口；站点文件仍由 GitHub Pages 托管，音频仍由 R2 的 `audio.aimaradio.com` 提供。

如果页面没有立即变化，先到 GitHub 仓库的 **Actions** 页面确认部署成功，再强制刷新浏览器缓存。

About 头像放在 `opt/radio/radio-info/avatar.JPG`，重新执行导入会同步到网站。更新 Oboro 等单期的图片后也需重新导入，再执行构建。Demo 推荐封面和列表封面共用绘制算法，按容器等比缩放。
